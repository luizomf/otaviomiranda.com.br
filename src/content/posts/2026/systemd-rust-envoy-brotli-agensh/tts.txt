O system D integra infraestrutura para novos programas em Rust.

O system D é o conjunto de ferramentas que inicia e gerencia serviços em muitas distribuições Linux.
Em vinte e quatro de outubro, o projeto incorporou a infraestrutura para criar programas em Rust.
A mudança está no código de desenvolvimento.
A adoção começa por programas novos dos quais os demais componentes não dependem, os chamados componentes de ponta.
O código C existente permanece, e a compilação continua organizada pelo Meson.

Os programas Rust ficam sem a biblioteca padrão da linguagem e se integram às bibliotecas C do projeto.
Para armazenar dados, usam implementações próprias de estruturas como Box e Vec.
Quando uma alocação fica sem memória, essas estruturas devolvem um erro que o programa pode tratar, seguindo as convenções do system D.

Outra decisão envolve os segredos guardados na memória.
O projeto associa a limpeza desses dados ao tipo usado para armazená-los.
Um vetor de bytes com a opção de apagamento limpa sua região de memória antes de liberá-la.
Mas essa garantia tem um limite importante.
Retirar elementos do vetor ou reduzir seu tamanho pode deixar os dados na memória até que o espaço seja liberado.
Ou seja, a retirada de um elemento não significa que seu conteúdo já foi apagado da memória.

O primeiro programa proposto para usar essa base é o system D keyring setup, que segue em uma mudança separada.
Para quem mantém software em C, o caso mostra que a adoção gradual também precisa definir as fronteiras de integração.
