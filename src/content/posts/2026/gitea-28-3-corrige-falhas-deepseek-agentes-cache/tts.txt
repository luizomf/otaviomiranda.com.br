A plataforma hospeda repositórios Git, revisões de código e automações.
Duas correções merecem atenção especial.

A primeira envolve a associação de contas.
O problema aparecia quando a associação automática estava ativada e o cadastro estava aberto.
Nessa configuração, uma pessoa autenticada por um provedor OAuth dois podia vincular sua identidade externa à conta de outro usuário.
Com isso, podia entrar sem a senha daquela conta.
A correção ajusta a escolha da conta vinculada.

A segunda falha envolve automações de revisão de código.
Um usuário com permissão apenas de leitura podia provocar a execução de código escolhido por ele.
Esse código tinha acesso aos segredos do repositório e a um token com permissão de escrita.
Havia uma condição: a branch de origem do pedido de revisão precisava estar no mesmo repositório.
A correção faz a automação usar o commit da ponta dessa branch.

A versão também fecha caminhos que ignoravam restrições de tokens.
Por exemplo, um token de administrador limitado a conteúdo público podia realizar operações administrativas, inclusive criar outros administradores.
Isso mostra por que a autorização precisa conferir duas coisas: os privilégios da conta e as restrições da credencial apresentada.

Agora, o protótipo da DeepSeek delimita tarefas, mas executa com os privilégios do operador.
O projeto se chama D S H superagent, e seu código inicial é datado de trinta e um de outubro.
É um protótipo de pesquisa que acompanha atividades de um repositório no "Git Hub" e, opcionalmente, conversas no "Feishu".
Quando aceita um pedido, cria uma tarefa com escopo autorizado e entrega a execução a uma sessão e um diretório próprios.

O desenho procura evitar trabalho duplicado.
Aceitar duas vezes o mesmo evento deve produzir uma única tarefa.
E cada conversa tem, no máximo, uma avaliação em andamento.
A fonte dos eventos também guarda sua posição de leitura, para evitar repetições depois de uma reinicialização.
A autorização fica a cargo do sistema que coordena o agente.
Comentários posteriores podem fornecer contexto, sem ampliar as permissões da tarefa.

Mas, na execução, os agentes rodam comandos sem aprovação.
E fazem isso com os privilégios do usuário do sistema operacional que os iniciou.
Os diretórios separados e os comandos intermediários organizam o trabalho, mas não oferecem isolamento de segurança.
Para exigir aprovação antes de incorporar código, a documentação recomenda proteção de branches.

O repositório se apresenta como código de pesquisa, com partes do desenho ainda não implementadas.
Quem for experimentá-lo precisa limitar os privilégios do ambiente de execução.

A próxima história mostra como um endereço novo guardou JavaScript antigo no cache.
Em relato publicado em primeiro de novembro, a criadora do "MyIPScan" descreve uma falha de atualização em seu site estático no "Cloudflare Pages".
A página passou a pedir JavaScript com um parâmetro de versão novo antes de o arquivo atualizado estar disponível.
Segundo ela, a C D N buscou o arquivo antigo e o guardou sob a chave nova.
A C D N é a rede que mantém cópias do conteúdo próximas dos visitantes.
Ou seja, naquele relato, o endereço era novo, mas a cópia guardada ainda era a antiga.

A resposta vinha com um prazo de validade de um ano e uma indicação de que o conteúdo não mudaria nesse intervalo.
Enquanto a cópia estivesse no cache e dentro desse prazo, o navegador podia reutilizá-la sem consultar novamente o servidor.
É o comportamento previsto no padrão que define essa indicação de conteúdo imutável, com exceção de uma atualização forçada pelo usuário.

Limpar a C D N não apaga as cópias já armazenadas pelos visitantes.
A prevenção proposta no relato combina duas medidas.
Uma é usar nomes de arquivo com hash do conteúdo, para que cada nome identifique uma versão específica.
A outra é publicar os arquivos antes das páginas que apontam para eles.
Também é preciso versionar as dependências.
Mudar o parâmetro do script principal não altera automaticamente os endereços dos módulos que ele importa.

A sequência do incidente é descrita pela autora; o padrão H T T P sustenta a explicação do cache.
Para quem publica sites estáticos, a lição é conferir se os arquivos atualizados já estão disponíveis antes de colocar no ar as páginas que apontam para eles.
